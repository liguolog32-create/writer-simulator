# 观澜 · 常驻可移动形象模块（AvatarLayer）· 程序设计 v1

> 需求（用户 2026-10-15）：**机器人创建成功后，就能以"可移动模块的个人形象"出现在网页中。**
> 分工：本文件只设计**程序与逻辑**（形象怎么存在、怎么动、状态怎么驱动、接口怎么留）；**视觉形象由用户后续设计**，通过下面的「皮肤契约」接入，**不改逻辑代码**。

---

## 一、为什么要分两层

```
AvatarLayer（本文件设计）     ——  它「是个什么人」：位置、状态、动作、交互、菜单、小面板
        ↓ 只通过一个契约通信
AvatarSkin（用户后续设计）    ——  它「长什么样」：素材、动作表现、装饰
```

**分离的好处**：
1. 用户做形象设计时不需要懂状态机与拖拽逻辑；
2. 换形象 = 换一份 skin 文件（可以做好几套，用户挑）；
3. 逻辑可以独立测试（位置计算、状态推导都是纯函数）。

---

## 二、存在方式（形态规格）

| 项 | 规格 | 理由 |
|---|---|---|
| 挂载点 | `AppShell` 内、与页面视图**并列**（不在任何 view 里） | 切页面它不消失——"常驻"的前提 |
| 定位 | `position: absolute`（相对 AppShell 容器），`transform: translate3d()` 移动 | 用合成层，拖动不掉帧 |
| 默认位置 | 视口**右下角**内缩 24px（避开常见的内容区与按钮） | 第一眼不挡事 |
| 尺寸 | 基准 `96×96`，可 `scale` 0.75–1.5 | 形象设计给的素材按 96 设计 |
| 层级 | `z-index` 介于内容与弹窗之间（弹窗永远在它上面） | 它不该挡住模态框 |
| 移动端（<640px） | **默认不显示**，只在机器人页显示 | 小屏遮挡严重，不值得 |
| 无障碍 | 可键焦、方向键微调位置、Esc 收起、`aria-label="观澜"` | |
| 隐身 | 可"隐身 1 小时 / 今天别打扰"；隐身时**不留任何痕迹** | 不用"小圆点"骚扰用户 |

## 三、它的三种"体态"

| 体态 | 触发 | 表现（逻辑层只给状态，形象层决定怎么画） |
|---|---|---|
| **自由体态** | 默认 | 完整形象，可拖动 |
| **停靠体态** | 拖到视口边缘自动吸附（左/右/下） | 贴边、半收起（比如只露半边），hover 或点击展开；**不占内容区** |
| **小面板态** | 单击 | 形象缩到面板一角，旁边展开对话小窗（见第六节） |

## 四、状态来源：它为什么动、为什么有表情

**核心原则**：形象的表情**不是随机的**，而是**从机器人状态推导出来的**——所以它"看起来在想事"，是因为它真的在处理。

```ts
// src/bot/avatar/presence.ts（纯函数，可单测）
export type AvatarMood =
  | 'idle' | 'look' | 'thinking' | 'curious' | 'pleased' | 'offended' | 'sleepy'

export type AvatarGesture =
  | 'none' | 'breathe' | 'look' | 'leanIn' | 'turnAway' | 'nod' | 'shiver' | 'wake'

export interface AvatarPresence {
  mood: AvatarMood
  gesture: AvatarGesture
  /** 头顶是否有"我有话想说"的小气泡 */
  wantsToSpeak: boolean
  /** 正在屏幕观察（必须在形象上有常驻可见的指示 —— 隐私硬要求） */
  observing: boolean
  /** 刚发生的内化判定（用于即时表情反馈，几秒后消退） */
  lastOutcome: ClaimOutcome | null
  /** 它对用户的亲疏（影响"它愿不愿意靠近你"） */
  warmth: number
}
```

### 情绪 / 动作触发映射表（**这张表就是形象设计的素材清单**）

| mood | 触发条件（来自 bot 真实状态） | 建议表现 | 时长 |
|---|---|---|---|
| `idle` | 默认 | 呼吸起伏 | 持续 |
| `look` | 光标移动 / 用户正在输入 | 朝向光标 | 持续 |
| `thinking` | LLM 生成中（`busy`） | 微皱 / 转圈 / 头顶三点 | 生成期间 |
| `curious` | 收到"复核"落点（同一条被反复提起） | 侧头 + 微微靠近 | 2s |
| `pleased` | 落点为 `internalized` | 点头 / 微光 | 3s |
| `offended` | 落点为 `resisted` / `backfire` | 别过脸 / 轻抖 | 3s |
| `sleepy` | 无互动 > 15 分钟 | 闭眼、慢呼吸 | 持续到被打断 |
| `speaking` | 它正在流式输出 | 口型或轻微律动 | 输出期间 |

> 形象设计只要给这 **7 种情绪 × 8 种动作** 的素材即可覆盖全部行为。

## 五、移动规则（含"它自己会动"）

### 5.1 用户拖动（最高优先级）
- `pointerdown` → 抓取（形象轻微放大 1.05 表示"被拿起来"，物理感）
- 拖动中：`transform: translate3d()`，**不触发重排**；若拖到边缘 40px 内 → 预览吸附位置（半透明影子）
- `pointerup` → 吸附或停在原地；**用户拖动后 30 分钟内它不再自主移动**（尊重用户摆的位置）

### 5.2 自主移动（真人感，可关闭）
它**会自己挪**，但遵守"社交分寸"：

| 触发 | 行为 | 为什么 |
|---|---|---|
| 有话说（`wantsToSpeak`） | 沿边缘**走**到靠近光标的那一侧（2.4s 缓动，是"走"不是"瞬移"） | 像人凑过来 |
| 被冷落 > 15 分钟 | 缩到最近的角落，进入 `sleepy` | 会累、会退场 |
| 用户长时间打字 | 稍微退开一点（不挡视线） | 有分寸感 |
| 被冷落后又被叫 | `wake` 动作 + 快速回位 | 有反应 |
| `offended` | 向远离光标方向挪一小段（40–80px） | 闹脾气 |

- 全部走 `prefers-reduced-motion` 检查：**开了就彻底不动**（只保留状态与表情）。
- 自主移动的**每一步都有可见的过渡动画**，禁止瞬间跳位。

### 5.3 位置持久化
- 存在 `localStorage`（按 uid 分开），**不参与云同步**（位置是设备相关的偏好，不是它的资产）
- 恢复时做**视口边界校验**：换了小屏/分辨率变了要自动收回可视区

## 六、交互规格（逐个手势）

| 手势 | 行为 |
|---|---|
| 单击 | 展开/收起**小面板**（形象缩到面板一角；对话、识海摘要、最近判定都能在这里看） |
| 双击 | 跳到机器人页（= "回它的房间"） |
| 拖动 | 移动 / 吸附 |
| 长按 或 右键 | 菜单：`回它的房间` / `隐身 1 小时` / `今天别打扰` / `让它睡一觉`（夜间巩固）/ `换形象`（日后） |
| Hover 1s（未展开时） | 显示一行"它现在的状态"（如"它在想你说的那句话"） |
| 键盘 | `Tab` 聚焦 → 方向键微调 → `Enter` 展开 → `Esc` 收起 |

### 小面板（展开态）
- 与机器人页**共用同一套对话逻辑**（抽 `useBotChat()` hook，两处复用，不重复实现）
- 只放最常用的三块：**对话** / **它刚长出的一条信念** / **本次判定落点**
- 底部一行入口：`去它的房间 →`（等于双击）
- **它说话时，形象与面板同时在场**：面板是"它跟你说话的地方"，形象是"它本人"

## 七、皮肤契约（**等你的形象设计来填**）

```ts
// src/bot/avatar/types.ts
export interface AvatarSkin {
  id: string
  name: string
  /** 按 96×96 设计；实际渲染会按 scale 缩放 */
  hitbox: { w: number; h: number }

  /** 7 种情绪的静态表现（图 / 矢量 / 帧序列都行） */
  moodArt: Record<AvatarMood, React.ReactNode>

  /** 8 种动作：可选。给了就播，没给就用 CSS 兜底 */
  gestures?: Partial<Record<AvatarGesture, {
    /** 播放时长（ms）；0 = 持续到状态改变 */
    duration?: number
    /** 程序化动作（改 transform / 换帧 / 播 Lottie 都行） */
    play?: (el: HTMLElement, opts: { reducedMotion: boolean }) => void | (() => void)
  }>>

  /** 说话时的处理 */
  speaking?: 'none' | 'bob' | 'mouth'
  /** 围绕形象的装饰（名字牌、影子、光环、观察中指示灯的位置） */
  chrome?: React.ReactNode
  /** 观察中的常驻指示：必须在形象自身上可见（隐私要求） */
  observingBadge: React.ReactNode
}
```

**接入方式**：新建 `src/components/avatars/<id>/skin.tsx` 导出 `skin: AvatarSkin`，在设置里选 id 即可。**不需要碰任何逻辑文件。**

**占位形象**：逻辑层会先带一个极简几何占位（一个圆 + 两只眼睛 + 状态色），让功能可以先跑起来，等你的形象到位直接替换。

## 九、性能与降级

- **静止时零 CPU**：呼吸/眨眼交给 CSS 动画；只有拖动与自主移动时才用 `requestAnimationFrame`
- 拖动只改 `transform`，绝不改 `top/left`（避免重排）
- `prefers-reduced-motion` → 关掉自主移动与动作
- 视口 < 640px → 不渲染常驻层
- 页面 `visibilitychange` 隐藏时暂停一切动画与自主移动

## 十、与已有设计的衔接

| 已有 | 关系 |
|---|---|
| 机器人页（`#/bot`） | 那是"它的房间"（完整功能）；悬浮形象是"它在网页里的存在"（轻量入口）。两者是同一份状态的两个视图 |
| 价值观萌芽 / 信念表 | 形象的表情与"有话说"气泡由它驱动（新内化 → `pleased`；被抵抗 → `offended`） |
| 屏幕观察 | **观察中必须在形象上常驻可见**（不只在小面板里）——隐私硬要求 |
| 识海记忆 | Hover 显示的状态文案从识海里取最相关的一条 |
| 上云白名单 | 形象位置**不进 AppState**（设备偏好），只在本地存 —— 不增加上云面 |
